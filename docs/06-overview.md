# Overview：進捗報告のための全体俯瞰

同一リポジトリで進む Spec の状態をまとめ、リーダーが上位へ報告する材料を確認する画面です。リーダーに承認や実行を依頼する場所ではありません。

## 表示構成

1. 全体件数：Total specs / In progress / Review pending / Verification pending / Needs attention / Verified complete
2. 報告サマリーと `Copy progress summary`
3. 要注意：明示されたブロック、メタデータエラー、検証失敗、手動確認、古い・未確認・取得できない検証結果
4. 進行中 Spec：工程、実装タスク完了数、記録された状態、更新時刻、検証状態
5. 検証済みの完了 Spec：検証日時とレポート。初期状態は折りたたみ

件数をクリックすると進行中一覧を絞り込めます。Spec を開くと成果物を参照し、検証の問題や完了項目からはレポートを参照できます。

## 集計の意味

- 完了：実装タスクがすべて完了し、現在の成果物に適用できる `impl-validation.md` の `DECISION: GO` が存在すること。
- 検証待ち：実装完了だが検証済みではない Spec。失敗・手動確認・古い結果も含みます。
- レビュー待ち：作業者側で承認待ちの工程がある状態。リーダーへの承認依頼ではありません。
- 要注意：記録に根拠のある問題。レビュー待ちという理由だけでは要注意にしません。

レビュー待ち・検証待ち・要注意の件数は重複します。足し合わせて総数にはしません。Spec ごとのタスク件数は粒度が異なるため、プロジェクト全体の完成率には換算しません。

## 報告用テキスト

`Copy progress summary` は最新のリポジトリ状態を再取得し、プロジェクト名・取得時刻・件数・進行中の工程と実装進捗・要注意理由・検証済みの一覧をクリップボードへコピーします。報告を送信する操作ではありません。

## 情報の範囲

ファイルに記録された状態を表示するスナップショットです。この VS Code ウィンドウの Run 状態は報告用集計へ含めません。ほかの作業者の未共有の変更まで同期する機能ではありません。

更新間隔から停滞を推測せず、残り時間や期間内の進捗差分も生成しません。依存候補は要注意の根拠にしません。Recent updates と Dependencies & candidates は削除しました。ローカル実行は Runs、作業履歴は Sessions で確認します。
